# Idea brainstorm — how we arrived at Seam

Idea developed in conversation with an AI assistant; the direction and the key
design constraint were ours. Coding was directed via our spec-driven workflow
(see `docs/specs/` and `docs/prompts/`).

## The path

We didn't want to reverse-engineer an idea from the sponsor list — the first
ideas we tried that way (prediction markets, a DeFi risk oracle) felt hollow,
and the risk oracle already existed as a tool The Graph ships themselves. So we
went the other way: find a real problem, then keep it only if each sponsor was
genuinely load-bearing rather than decorative.

The turning point was reframing away from another "monitor something and prove
it happened" tool, toward a system where **nobody has to reveal their position
first.**

## The constraint that shaped it

An early version used a single number and a plain comparison — and used no AI at
all. That failed 0G's requirement to use 0G Compute for *inference*, and it was
too simple to be real: a negotiation is many dimensions that trade off. That
forced the final shape — each side writes a full position in plain language, and
a model inside a sealed enclave judges whether a deal exists. The AI is the
product, not an add-on.

## Result

**Seam** — sealed two-party negotiation. Both sides write their terms; a pinned
model in a 0G TEE returns one line — whether a deal is possible — without either
side, or us, seeing the other's terms.

It passes the load-bearing test — remove any one sponsor and it breaks:

- **No 0G:** the comparison isn't private, so no counterparty would use it.
- **No Hedera:** either side can stall past the deadline or deny their terms.
- **No World:** repeated submissions reconstruct the other side's position.
